# CXWorks website — editable source

This folder is the unpacked version of `CXWorks_Sit.html`. That file was a **self-unpacking bundle** exported from Claude Design: every image, font, script and the page template were gzipped + base64'd into one 2 MB HTML file, and a loader script inflated them into memory on page load. Nothing was editable by hand.

Here every piece is a real file. The site looks and behaves exactly the same.

## Quick start

| What | How |
|---|---|
| View the site | Open `index.html` in a browser (works from `file://`, no server needed) |
| After editing a template in `src/` | `node build.js` (or `node build.js --watch` while you work) |
| After editing CSS, `js/app.js` or a data file | Just refresh — no build needed |
| Local server (optional) | `npm run serve` or VS Code Live Server |

## How it runs

It is a single-page app with hash routes (`#/`, `#/services/digital-merchandising`, `#/insights/digital-cx` …).

1. `index.html` loads React 18 and `js/vendor/dc-runtime.js` (the Claude Design template engine).
2. The data files in `js/data/` load and build `window.CXD.pages` — **every page is an object with a list of blocks** (`hero`, `stats`, `faq`, `cta` …).
3. `js/app.js` reads the URL hash, picks the page, and exposes the values the templates bind to.
4. The runtime renders the `<x-dc>` template using `{{ value }}`, `<sc-if value="…">` (show/hide) and `<sc-for list="…" as="x">` (loops). For a normal page it loops over `blocks` and shows the partial whose `b.is_<type>` is true.

## Common edits

**Change text on a page** — find the page in `js/data/05-site-structure.js` (e.g. `P['nine-gates'] = { … }`), or its title/meta/hero override in `01-page-copy.js`. Search for the sentence you see on screen; most copy lives in the data files, not the templates.

**Change how a section looks** — edit its partial, e.g. `src/templates/blocks/faq.html`, then `node build.js`. Styles are mostly inline `style="…"` using the CSS variables from `css/main.css`.

**Change brand colours** — the `:root{ --bg, --ink, --acc … }` line at the top of `css/main.css`.

**Add a page** — in `05-site-structure.js`, add `P['my-page'] = { title: '…', blocks: [ { type: 'text', eb: '…', h: '…', p: '…' }, { type: 'cta' } ] };`. It is live at `#/my-page`. Reuse any existing block type.

**Add a new block type** — 1) create `src/templates/blocks/mytype.html` wrapped in `<sc-if value="{{ b.is_mytype }}">…</sc-if>`; 2) add `<!-- @include blocks/mytype.html -->` in `src/templates/views/page.html`; 3) use `{ type: 'mytype', … }` in a page; 4) `node build.js`. If the block needs computed values, add them where `js/app.js` maps blocks (search `b['is_' + b0.type]` — the per-type `if (b0.type === '…')` branches follow it).

**Add an insight article** — copy any file in `js/data/blog/`, give it the next number, change `slug`, `t`, `title`, `d` and the body, then `node build.js` so the new script tag is added. It appears at `#/insights/<slug>`.

**Form endpoint / support emails** — `CONFIG` at the top of `js/app.js`.

## Notes

- Editing `index.html` directly works, but the next `node build.js` overwrites it.
- The console shows a few harmless `<path> attribute d: "{{ … }}"` messages on load: the browser briefly sees the raw template before the runtime replaces it. The original bundle did the same.
- `flagcdn.com` country flags load from the internet; everything else is local.
